# Study Vault

A personal revision library for UPSC / UPPCS preparation: your notes, plus navigation, search,
active recall, spaced revision, PYQ filters and progress, all in one reader.

**Open `index.html`** in Chrome or Edge. There's no server, no install and no account. Everything
runs locally. Web fonts load when you're online and fall back to system fonts when you're not.

**Online and on your phone:** the Vault is published at <https://study-vault-mocha.vercel.app> and can be
installed as an app. On Android Chrome, use ⋮ › *Install app* / *Add to Home screen*; on iPhone Safari, use
Share › *Add to Home Screen*. Once installed it works fully offline, including the original notes files
(subject page › *Open the original notes file*). Progress is stored per device and browser, so move it with
Settings › Export / Import.

## Folder layout

```
index.html              the app (open this)
manifest.webmanifest    install metadata (name, icons) for the phone / desktop app
sw.js                   offline service worker, generated by the build (don't edit)
sources/                your notes files, read by the build, never written by it
templates/              starting file for new subjects (see NOTES_FORMAT_GUIDE.md)
backups/                originals and change reports from edits made to a notes file
Build Vault.cmd         double-click after adding or updating a notes file
vault.config.json       optional: subject name / colour / order
data/                   generated by the build (don't edit); data/sheets/ holds the published notes files
app/                    the application (css + js + icons)
tools/                  the build (Node.js, no dependencies)
```

## Publishing an update

1. Build (above).
2. Run `npx vercel deploy --prod --yes` in this folder. The folder is linked to the `study-vault` project.

Only `index.html`, `manifest.webmanifest`, `sw.js`, `app/` and `data/` are uploaded (see `.vercelignore`).
Each build gives `sw.js` a new version, so installed copies pick up the update the next time they're
opened.

## Adding a subject

New subject files must follow **[NOTES_FORMAT_GUIDE.md](NOTES_FORMAT_GUIDE.md)** and start from
`templates/Master_Sheet_TEMPLATE.html`. The guide covers the exact format, a pre-flight checklist and how
to read the build output.

1. Put the file in `sources/`, e.g. `Geography Master Sheets.html`.
2. Double-click **Build Vault.cmd**, or run `node tools/build.mjs`.
3. Reload `index.html`. The subject appears on the dashboard, in search, recall, revision and the PYQ explorer.

The subject id comes from the file name, ignoring "Master Sheet(s)", "notes" and version tags:
`Geography Master Sheets.html` and `Polity_Master_Sheet_v2.html` become `geography` and `polity`. To rename a
subject, change its colour or reorder it, edit `vault.config.json` and rebuild. Rebuilding never touches
your progress.

**Updating a subject to a new version:** remove the old file from `sources/`, add the new one, and rebuild.
Progress carries over for every section that keeps the same sheet and heading.

Supported formats (detected automatically; each keeps its own markup rules):

- **Master Sheet v2** (the current Polity file). The notes live in the page's script as `SEC({...})`,
  with sheet tiers, exam stats, block tiers and the UPPCS Mains tag family. Since Sept 2026 it can also carry
  **figures**: inline SVG diagrams and maps, and compressed photos (guide §14).
- **Master Sheets v1**. The notes live in the page's script as `SHEETS.push({...})`.
- **Plain HTML** (fallback). `<h2>` becomes a sheet and `<h3>` a section. Tables and lists are kept
  verbatim; scripts, styles and event handlers are stripped.

The two Master Sheet formats get everything: exam tags, traps, recall prompts and the fidelity check.

## The notes are never modified

- The build **executes each source file's own script** in an isolated sandbox. What the vault shows is
  exactly what the file shows, including the file's own clean-up pass.
- After extraction, the build renders every line with the vault's renderer and **compares it against the
  source's own renderer**. Any difference fails the build.
- Polity (v2) result: all 1,960 lines, all 203 column headers and all 88 sheet notes and stats lines are
  identical to the source's own rendering. If a source's renderer ever hides part of a line, the vault
  shows the full line and the build lists it.
- Figures are checked for safety and size (no scripts, no remote references, colours from the theme,
  size caps), and each one must come out of both renderers as identical markup. A figure that fails is
  reported, never silently cleaned up.
- Everything the app adds (search keys, recall prompts, schedules, progress) is derived or stored
  separately. Recall mode only blurs spans; it never rewrites text.

## Studying

| Area | What it does |
|---|---|
| **Reader** | Sheets and sections with breadcrumbs, a jump-to-section menu, previous/next section and sheet, bookmarks, and resume where you left off. |
| **Recall mode** (`r`) | Answers blur, you think, then reveal (click or `Space`). Tables hide the answer columns, or reverse to hide the first column (*identify the Article*), or hide one column (*identify the year*). Facts use the cue already in the line (`cue :: answer`, text before `—` or `:`), or hide the bold key terms. Rate each section **Again / Hard / Good / Easy**. |
| **High-yield filter** (`h`) | Shows only PYQ-tagged lines, traps and highlighted distinctions. You can also filter by exam. |
| **Revision** | Sections enter the queue the day after you first read them. Ratings set the next gap (Again → today; Good grows ≈2.5×). Missing a line in a drill pulls its section back to tomorrow. Sheets are interleaved. |
| **Recall drills** | Mixed (interleaved across sheets and subjects, with due and weak material first), PYQ (by exam and year), Trap, Weak areas, or a custom drill. Every prompt links to its exact source line. |
| **PYQ explorer** | Every tagged line by exam (UPPSC, UPSC CSE, CDS/NDA, CAPF, other PCS) and year, with a per-year chart. |
| **Search** (`Ctrl K` or `/`) | Searches every line, heading, Article number, year and exam tag, and jumps to the exact line. |
| **Progress** | Coverage per sheet, activity, recall accuracy, weak sections, most-missed lines and history. |

Keyboard: `j`/`k` next/previous section · `[`/`]` previous/next sheet · `o` jump to section ·
`b` bookmark · `t` section outline · `f` focus mode · `m` navigation · `?` all shortcuts.
In recall: `Space` reveal next · `a` reveal all · `1`–`4` rate.

## Your progress

Progress is stored in this browser's local storage, separate from the notes, and is private to the
browser profile. Use **Settings › Export progress** now and then as a backup, or to move to another
device (**Import backup**).
