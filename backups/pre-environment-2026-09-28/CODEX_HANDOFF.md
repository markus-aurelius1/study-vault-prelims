## 1. Project summary

Study Vault is a personal, offline-first revision web app for one aspirant preparing for UPSC CSE Prelims and
UPPCS Prelims (and, secondarily, CDS/NDA, CAPF and other state PCS papers). A Node build reads the user's
subject notes files (self-contained HTML "Master Sheets" in `sources/`) without changing a word. It verifies,
line by line, that the app renders every line exactly as the file's own renderer does, and then publishes a
static PWA. The PWA offers navigation, search, active-recall modes, section-level spaced revision, PYQ
(previous-year question) filters and progress tracking. Polity and Geography are live; Geography (subject #2) was
written by an AI agent in reviewed batches from the user's raw notes and PYQ compilations and deployed on
2026-09-28. Economy, History, Environment and Science & Tech are planned, one subject file each.

`.vercelignore` publishes only `index.html`, `manifest.webmanifest`, `sw.js`, `app/` and `data/` (minus
`data/registry.json`). `sources/`, `drafts/`, `raw-sources/`, `templates/`, `backups/`, `examples/`, `tools/`
and the markdown files stay local.

### 3.2 Data flow

```
sources/<Subject>_Master_Sheet_vN.html
   │  node tools/build.mjs
   ├─ pick adapter (first match wins): master-sheet-v2 (`const S=[]` + `SEC({`) → master-sheets v1 (`SHEETS.push`) → generic-html
   ├─ lib/sandbox.mjs: run the file's own inline <script> in node:vm with inert DOM stubs; inject an export just
   │  before the LAST "})();" to capture the file's renderer (fmt, blockHTML, KEY, GROUPS)
   ├─ ids: subject id from the file name (guide §3.1); sheet id as written; section id = slug(h), 64 chars, "-2" on collision
   ├─ lib/figures.mjs: safety/size checks on every `fig` (allowlisted SVG, theme tokens only, caps). Any problem → subject not built
   ├─ lib/verify.mjs: render every block with app/js/markup.js + render.js (the browser's own files) in a VM and compare
   │  with the file's renderer: each line's text, headings, column headers, sheet note/stats, figure markup (character for character)
   └─ write data/subjects/<id>.js · data/sheets/<id>.html (source + "← Study Vault" link) · data/manifest.js · data/registry.json · sw.js
   ▼
index.html → data/manifest.js + data/subjects/*.js → app/js: markup → render → util → store → content → views/reader,
pages, study, insight → app (router)
```

The central invariant: **the Vault shows exactly what the notes file shows.** Nothing in `app/` rewrites note
text. Recall only wraps spans around existing text to blur them, and filters only hide whole lines. Search keys,
prompts, schedules and progress are derived and stored separately.

## 4. Output Quality Specs

### 4.0 Rules that apply to all content

1. **The user's notes are authoritative and immutable.** Never rewrite, paraphrase, summarise, correct, reorder,
   merge or delete the content of a notes file the user supplied (today: `sources/Polity_Master_Sheet_v2.html`),
   even to fix an error. Surface problems instead. Content edits happen only when the user explicitly asks; then
   follow §4.4.
2. **A PYQ tag is a claim that a real paper asked this fact.** Tag only questions you have verified in the PYQ
   compilations or answer keys. Never infer a year. When unsure, leave the tag off and list the item under
   "Please check" in the batch report (§4.3).
3. **No visible source names** in anything the user studies: no book, PDF, coaching brand, toolkit or document
   named as the origin of a fact, in lines, `stats`, `note`, captions or alt text. Keep the reasoning, drop the
   attribution. Write "the 2023 key treated X as false because …", never "per <book>".
4. **UPPCS is the exam; UPPSC is the Commission** (guide §7.6): `[UPPCS 2023]`, `[UPPCS M 2010]`, but "the UPPSC
   key", "other UPPSC papers".
5. **No AI summaries or invented content in the app.** Everything the Vault adds is derived from the notes'
   structure (§4.5).
6. **Prelims only.** UPPCS Mains answer-writing is a separate project; don't add Mains features or content.
   Objective old UPPCS Mains questions are still tagged `[UPPCS M yyyy]`.

### 4.1 Subject notes files (Master Sheet v2)

**Where:** `sources/<Subject>_Master_Sheet_v<N>.html` (live) and `drafts/…` (in progress). Mechanics (syntax,
fields, tag grammar, build errors) are defined in `NOTES_FORMAT_GUIDE.md`. Look them up there and don't
paraphrase them from memory. This entry covers the content bar the guide doesn't state.

**Two modes, different rules:**

| | User-supplied file (Polity) | Commissioned subject build (Geography, and later subjects) |
|---|---|---|
| Who writes content | the user | an AI agent, from the user's raw notes + PYQ compilations + reference material |
| May the agent change facts? | No (§4.0.1) | Yes: synthesise, correct slips in place, and **report every correction** |
| Must preserve | every character | the *substance* of every correct, relevant item in the user's notes (a preservation pass before each delivery) |
| Delivered as | n/a | batches of 3–5 sheets, each reviewed by the user before the next (§4.3) |

#### What "good" looks like

**File.** One subject per file, started from `templates/Master_Sheet_TEMPLATE.html` with only `<title>`, `<h1>`,
`<span class="sub">`, the search placeholder and the CONTENT region changed. Subtitle `UPSC CSE Prelims · UPPCS
Prelims`. Geography as drafted (planned at about 250 blocks and 2,400 lines): 30 sheets, 438 blocks, 3,837 lines
and 45 SVG figures (140 KB); the file is about 780 KB. Polity: 22 sheets, 188 blocks, 1,960 lines, about 350 KB.

**Sheets.** A chapter-sized topic. Groups follow the syllabus and end with a **Revise** group holding a
"Numbers & Trap Bank" sheet and an "Exam Radar — UPSC & UPPCS" sheet. `tier` expresses importance across *both*
exams (1 = learn cold, 2 = regular, 3 = skim).
- `stats` is **exactly 3 lines**, in the shape `UPSC CSE: …` / `UPPCS Pre: …` / `Formats: …`, with real counts and
  where the exams diverge. Real example (Geography sheet 01):
  `"UPSC CSE: 11 Q (2009–25) in 8 of 17 papers, 5 of 8 since 2018 — 4 in 2025 alone (time zones, date line, Earth’s spin, Equator lakes); astronomy items mostly before 2012"`,
  `"UPPCS Pre: 2 Q (2018–25); older UPPSC papers asked solar-system, latitude and local-time basics about 75 times (1990–2017)"`,
  `"Formats: how-many (time zones), Statement I–II (date line), day length on 21 June, local-time arithmetic, planet ↔ feature matching"`.
- `note` is 1–2 sentences, about 25–40 words: what the sheet covers, how it connects and what belongs elsewhere.
  Real example: `"The layered Earth as seismic waves reveal it, the three rock families and how each turns into the others, and the long clock of Earth history. Plate movement, volcanoes and earthquakes follow on the next sheet."`
- No testable fact lives only in `stats` or `note`: they are never searched or drilled.

**Blocks.** One sub-topic each, sized like a revision card: 3–25 lines (Geography median 6, Polity median 9).
Headings are plain, specific and permanent (`"Solstices and equinoxes"`, `"Countries on the Equator, Tropics and
Prime Meridian"`). `t` marks what the exams actually test as 1 even inside a tier-2 sheet. Use `k:"trap"` for trap
sets and elimination lists (Polity: `"FR — trap set"`, `"Not in the DPSP — elimination list"`, `"Answer-key quirks — decided"`).
**One block, one clean account:** never a "PYQ facts" block plus a "background" block that restates it.

**Lines.** One fact per line, as a **falsifiable statement**, because the dominant question formats (how-many
statements, Statement I–II, Assertion–Reason) test each clause separately. Measured: median about 19–20 words
excluding tags, 90th percentile about 32–35. The new-subject standard (Geography Batch 1):
- **Every** line bolds its key term or number (Batch 1: 100% of list lines; Polity: 76%, which the guide now
  treats as a defect).
- Most lines use `prompt :: answer` (Batch 1: 76% of list lines). The prompt is a real question stem and the
  answer is the exact fact, followed by the trap and then the tags: `"Land : water ≈ **29 : 71** (roughly 1 : 2.4) :: !!not 1 : 4!! [CSE 2005]"`.
- `!!…!!` names the actual wrong option examiners used or will use; `==…==` marks the distinction that decides a
  question; a backtick marks a number or entry: `` `1,475 lakh km²` ``.
- Tags go at the end, merged into one bracket, newest year first within an exam (23 of 24 multi-year groups in
  Batch 1): `[CSE 2011, 2008; UPPCS 2020, 2010, 2008; UPPCS M 2007]`. About 70% of list lines and 50–60% of table rows carry
  a tag; untagged lines are syllabus-core context, not trivia.
- Spatial and sequential facts are written in geographic order, not alphabetical: west → east, north → south,
  source → mouth, by latitude. Location answers name the exact neighbours, because the commonest UPSC trap is a
  real feature "one row off".

**Tables.** Column 1 is the key being asked (line, river, pass, planet, date). Keep cells short. The last column
is the "exam hook" (traps + tags) when there is one. Use at least 2 columns; 3 is the norm (84 of 107 Geography
rows, 540 of 855 Polity rows). Name year columns `Year` or `Date`.

#### What to avoid (failure modes already corrected)

- Restating one concept across several lines for different years. Merge them into one line carrying every tag
  (Polity had 5 lines restating "constitutional government = limited government"; they were merged on 2026-09-26).
- Copies of one fact that drift apart between a thematic sheet and a reference sheet (Articles, Numbers, Radar).
  Every copy carries the same particulars and the same tags.
- Lines with no bold, no backtick and no cue separator: they can never be tested in Recall (82 of 1,105 Polity list lines).
- Depth set by PYQ count alone. Syllabus-core mechanisms with few PYQs (pressure belts and ITCZ shift, monsoon
  jets, ocean gyres, air masses and fronts) still get full treatment, because new questions come from there.
  Untested, non-central trivia is left out (e.g. moon counts per planet, which also go out of date).
- Dropping the user's correct material because rebuilding is easier. A preservation pass against the raw notes
  runs before every delivery. In Batch 1 it restored recent eruptions, universe theories, star types and magma types.
- A clean build treated as proof of quality. The build checks syntax and renderer fidelity only; accuracy,
  priority, redundancy and tags need their own review.
- Embedding images from the user's notes or reference PDFs: they carry NCERT/branded watermarks. Redraw them as SVG (§4.2).
- `[PYQ 2024]`-style markers copied from the raw notes: they don't name the exam. Verify, then convert or drop.
- Growing a batch because the build loop is fast. Batch size is set by what the user can review.

#### Edge cases

- **Disputed or odd answer keys:** tag the question, state the keyed answer and the reasoning, and say which
  exam keyed what (Polity "Answer-key quirks — decided"). Flag new disputes in the batch report.
- **Changed conventions** (e.g. geological time-scale dates): use current values (Cambrian 539 Ma) and flag
  where older textbook values would change a keyed answer.
- **Provisional keys:** `[CSE 2026]` tags come from the provisional key of CSP-26; one question in that paper
  was dropped. Recheck against the final key when it is published.
- **Topic at a subject boundary:** cover only this subject's angle, briefly (Geography: MSP, farm tech and GM
  crops → Economy; deep astrophysics → Science & Tech, but a compact star/galaxy block stays; protected areas →
  Environment, with parks kept only as location cues).
- **A fact that needs a photo or detailed map:** write `/* PHOTO: what it should show */` in the content region.
  The user adds the image (guide §14.6).
- **Very long inputs:** read each batch's PYQs and reference chapters in full, and save the PYQ key map to a
  scratch file so it survives context compaction.

#### Per-batch checklist (run before every delivery)

1. Guide §13 pre-flight checklist, item by item.
2. A lint for what the build doesn't catch (guide §11.3): duplicate sheet ids and headings, malformed tags,
   list lines without bold/backtick/cue, tags not at the end, `UPSC CDS` / `UPSC CAPF`, `UPPSC` used as an exam.
   No lint script is committed yet (§10). Write one in scratch or add `tools/lint.mjs`.
3. Build on a **scratch copy** (§8) and require: `· master-sheet-v2`, `N/N lines identical`, `F/F figures
   identical`, no line starting `!` or `✗`, last line `Done`.
4. Figure checks (§4.2).
5. Preservation pass against the raw notes, and a source-name scan (`PMF|Toolkit|NCERT|coaching|according to`).
6. Write the batch report (§4.3), with the real build output pasted in.

### 4.2 Figures (SVG diagrams and maps in notes files)

**Where:** the `fig` field on a block (guide §14). Checks: `tools/lib/figures.mjs`. Approved examples: the 8
figures in `examples/geography-notes/batch-01_sheets-01-04.js` (orbit and seasons, sunlight on 21 June, interior
and shadow zones, rock cycle, plate boundaries, intrusive landforms, a river from source to mouth, drainage
patterns). A minimal example is the template's sheet 03.

**What good looks like:**
- An SVG in a landscape `viewBox` 640 wide (Batch 1: 640 × 300–400), 1–3 KB each (14 KB for all 8). Few labels,
  at least 15 units high, key labels 16–17 and bold. Label halos:
  `style='paint-order:stroke;stroke:var(--sheet);stroke-width:4;stroke-linejoin:round'`. Arrows use a `<marker>`
  whose id is `<sheet-id>_name`.
- Colour only through the 20 theme tokens: water `--navy`/`--navy-bg`, flows `--teal`, the thing to notice
  `--omr`, relief `--warn`, the Sun `--mark`. Nothing may disappear in dark mode.
- `alt` names every labelled feature (search reads only `alt` and `caption`). `caption` is one sentence giving
  the takeaway: `"Seasons come from revolving on a tilted axis whose direction never changes. The Earth is nearest the Sun in January, during the northern winter."`
- **Label with cues, never answers:** a figure is never blurred. Every fact it shows is also a line.
- Placed where position, direction or shape *is* the fact. Aim for about 1–2 per sheet and roughly 40 for Geography.
- **Maps** (from Batch 4): drawn from real longitude/latitude, not by eye. A scratch script projects coordinate
  lists to SVG paths — all-India 640 × 590 with `x = 50 + (lon − 67.5) × 17.5`, `y = 20 + (37.3 − lat) × 17.5`;
  the Peninsula south of 24.6°N 640 × 500 with `x = 20 + (lon − 68) × 28.5`, `y = 15 + (24.6 − lat) × 28.5`.
  From Batch 6, crowded maps get their labels from a greedy placer in the scratch `mkfigs_b6.py` (it avoids the
  coastline, drawn routes and rivers, dots and other labels; a 14 px IBM Plex Sans label occupies baseline −15 to
  +6), with a few labels pinned by hand where leaders would cross. Examples: "Where the mines are" (`minerals`),
  "Coal and oil fields" and "Nuclear power stations" (`energy`), "Highway corridors" and "Ports on the map"
  (`industry-transport`). Batch 8's world maps (`mkfigs_b8.py`) use coarse real outlines at 16–31 units a degree;
  area labels (countries, seas) are centred by a spiral search that avoids lines, point labels go through the
  placer. Water that runs off the map is drawn fill-only, with coasts as open lines, so the frame edge is never
  stroked. Examples: "Lakes of Africa’s rift", "Where the Great Lakes lie" (`world-physical`), "From the
  Mediterranean to the Gulf" (`world-seas`).
  Land `--paper`, sea `--navy-bg`, rivers `--navy`, the Western Ghats a translucent `--warn` band, sources
  `--omr` dots. The caption starts "Schematic." and the alt says "not to scale". Reuse the same coastline lists
  for later India maps so they match. Real examples: "Peninsular rivers" (`rivers-south`) and "Two branches of the
  monsoon" (`india-climate`).
- Schematic diagrams (river trees, confluences, cross-sections) need no coordinates, but tributaries must join in
  true order and on the true bank (e.g. the Panch Prayag and "Ganga tributaries west to east" in `rivers-north`).

**Verify:** the build (`F/F figures identical`), then label overlap and clipping in a browser. The preview pane
is often hidden and screenshots come back blank, so check each `<text>` with `getBBox()`. PyMuPDF renders SVG
geometry but not paint-order halos. Ask the user to look at one figure in dark mode.
The check used since Batch 4 runs in the page (served on 127.0.0.1): for every figure SVG of a sheet it flags
text boxes that overlap, text outside the `viewBox`, and any stroked path or line whose points (sampled every 2
units with `getPointAtLength`) pass through a text box. Batch 4 shipped with zero hits. Run it after
`await document.fonts.ready`: before the webfont loads, text boxes are narrower and a crossing can pass unseen. For true renders
(markers, halos, dark tokens) use headless Chrome: `chrome.exe --headless=new --window-size=W,H --screenshot=<abs
path> file:///<page>` on a page that defines the 20 tokens in `:root`; the output path must be absolute.

What the agent sends after each batch. The Batch 1 report (2026-09-27) is the reference instance; the user
accepted it and asked that quality not degrade. Plain language, no self-congratulation. Order:

### 4.4 Change report for edits to an existing notes file (only on explicit request)

**Reference instance:** `backups/Polity_v2_changes_report.html`, with `backups/Polity_v2_content_edits.json`
and the untouched original `backups/Polity_Master_Sheet_v2.original.html` (178 edits, 2026-09-26).

**Procedure:**
1. Back up the original to `backups/<File>.original.html`.
2. Apply each edit as an exact find → replace against the original.
3. Verify mechanically before writing: every distinct citation is still present, globally and per sheet (Polity:
   all 179 distinct citations; tag instances went 2,363 → 2,834), every section heading is unchanged (188/188),
   and the build shows `N/N lines identical`.
4. Never attach a tag to a sub-fact it may not belong to. When a reference row bundles several facts, the row
   gets the union of the tags, but the thematic lines don't inherit the row's tags.

**Report format:** a self-contained HTML page (light/dark, `<ins>` green and `<del>` red diffs). It opens with a
lead paragraph stating the edit count, the checks and their numbers, and the backup path. Navigation is by
request item with counts. Each edit is one `<article>` with an id (`E24`, `K1` …), the pair or cluster it
belongs to, and a word-level diff. A final **"Found, not changed"** section lists problems seen but left alone
(71 in Polity). The JSON holds `{id, item, pair, note, old, new}` per edit.

### 4.5 Derived study content in the app

**Where:** `app/js/content.js` (`C.variants`, `C.variantLabel`, `C.promptHTML`), `app/js/markup.js`,
`app/js/store.js`. Never generated text: every prompt is the note line itself with spans blurred.

- **List lines** take the first matching shape (guide §8.1). `prompt :: answer` → label "Fact → what the trap gets
  wrong"; a short cue before ` — `, `: ` or ` = ` → "Complete the fact"; bold or backtick terms only → "Fill in
  the key terms"; no shape → blurred in the reader but never drilled.
- **Table rows:** "Recall the row · <col 1> given". "Identify the <Article/…>" appears when column 1's header
  starts with Art, Article, Amdt, Sch, Part, Age, Year, Date, Case, Committee, Body, State, Act, Writ, Source,
  Office or List, or when the cell is 14 characters or fewer. "Identify the year" or "date" is added for
  `Year`/`Date` columns.
- **High-yield lines** (a valid tag, `!!`, `==` or a `k:"trap"` block) also get **"Why is this true?"**
  (self-explanation).
- **Revision:** day-based and SM-2-style per section. A section is due the day after its first read; Again →
  today, Good grows the gap by about 2.5×; a missed drill line pulls its section to tomorrow. Self-written cards
  are scheduled as `card:<id>`.
- **Personal layer** (in scope since 2026-09-26): per-section notes, doubt flags, self-written cards, "why"
  prompts, a pretest before reading (an unread section opens blurred once per visit) and reasoned highlights
  capped at 15 per sheet.

### 4.6 App UI copy

Real examples: "Sections come back just before you would forget them. Rate honestly: **Again** brings a section
back today, **Easy** pushes it weeks out." · "Nothing yet — history starts with your first read." · "You're
clear for today."

- Calm, factual, second person; sentence-case headings ("Spaced revision", "Due now").
- No exclamation marks (none in `app/js`), no emoji, no gamification copy.
- Spaced em dash ` — ` for asides (56 uses vs 3 en dashes); ` · ` as a separator; `→` in labels.
- Numbers through `V.num` (`en-IN` grouping).
- Empty states say what will fill them and how.
- Lede paragraphs explain the mechanism in one or two sentences ("nothing is removed from the notes, the rest is
  just hidden").

## 7. Conventions

- **Code style** (no formatter; match the surrounding code): `"use strict"` IIFEs, double quotes, semicolons,
  2-space indent. Long single lines (150–250 characters) are normal. Short `const` arrow helpers. Every file opens
  with a `/* … */` block saying what it does and why; comments give reasons. Build code is ESM `.mjs` using Node
  built-ins only.
- **The two-renderer rule:** `app/js/markup.js` + `render.js` must produce the same visible text as each notes
  file's RENDER region, and the same figure markup character for character. Change `figHTML`/`imgSize` in both
  `render.js` and the template, or in neither.
- **Generated files** (`data/**`, `sw.js`) are only ever written by `node tools/build.mjs`.
- **Ids are permanent:** subject words in file names, sheet `id`s and block headings are progress keys.
- **Notes file naming:** `<Subject>_Master_Sheet_v<N>.html`, one version per subject in `sources/`. Archive old
  versions in `sources/old/` (subfolders are ignored).
- **Before changing code or docs**, copy every file you'll touch to `backups/pre-<change>-<YYYY-MM-DD>/`,
  mirroring paths (as in `backups/pre-figures-2026-09-27/`). Git now exists but agents don't commit, so this
  is still the diff baseline for uncommitted work.
- **Guide sections are cited by number** in the user's own generation prompt (§11–§14). Append new sections;
  never renumber.
- **Drafts vs sources:** a subject stays in `drafts/` until every batch is approved; it moves to `sources/` only
  at final assembly.
- **Scratch builds:** `tools/build.mjs` resolves `ROOT` from its own location, so `node <copy>/tools/build.mjs`
  builds the copy and never touches the real `data/`.
- **Language:** plain English, Indian number grouping where the notes use it (`lakh`, `1,475`), typographic
  characters (`’ “ ” — → ° ²`) written as characters, never entities.
